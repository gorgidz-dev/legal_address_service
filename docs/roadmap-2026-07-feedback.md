## 2. Этапы

Оценки — в рабочих днях одного человека, без учёта согласований.

### Этап 1. Правовые документы — ждём юриста

Замечание: «подгрузим корректные документы, некоторые нюансы пропущены».
Тексты готовит юрист, я подставляю. Сейчас в `sections/LegalPage.tsx` лежат три
документа (политика, согласие, оферта), написанные без юриста, — их и надо заменить.
Самый дешёвый по работе и самый дорогой по последствиям пункт.

### Этап 2. Тексты и формулировки — СДЕЛАНО

Файлы: `sections/HomeSteps.tsx`, `HomeCases.tsx`, `HomeForOwners.tsx`, `HomeFAQ.tsx`,
`HomeConfigurator.tsx`, `publicCatalog.tsx`, `App.tsx`, `design/sections.css`.

1. Единое обращение на «вы» — 18 мест в 7 файлах. Проверка сплошным разбором
   строк, а не грепом: три места («Попробуй обновить страницу», «напиши нам»,
   «Проверь почту») нашлись только вторым проходом, потому что первый искал
   заранее выписанный список слов.
2. Четыре шага — в повелительном наклонении: «Выберите адрес» / «Отправьте
   заявку» / «Оплатите счёт» / «Получите документы».
3. Расшифровка комплекта документов — полосой под шагами: гарантийное письмо
   (согласие собственника), выписка ЕГРН (право собственности), договор аренды
   (основание для регистрации).
4. Блок «Что происходит до публикации карточки» → «Как мы защищаем вас от рисков»
   с новыми заголовками карточек.
5. Карточки для собственников — четыре переформулировки.

Отклонения от исходного документа и их причины — в разделе 4.

### Этап 3. Форма поиска заметнее — 0,5 дня

Увеличить поле ввода, добавить иконку лупы и кнопку «Найти».
Файл: `sections/HomeConfigurator.tsx`, стили в `design/sections.css`.
Форма недавно выровнена по колонке страницы — менять придётся внутреннюю раскладку,
не внешнюю ширину.

### Этап 4. Раздел «Цены и тарифы» — 1 день

Что входит в стоимость (аренда, документы, поддержка, продление), из чего
складывается цена, за что доплата (корреспонденция). Диапазон цен берём из выдачи
каталога, а не хардкодим.

### Этап 5. Акцент «Для собственников» — 0,5–2 дня

Минимум — блок на первом экране («Есть адрес? Сдайте его через маркетплейс»).
Максимум — отдельный лендинг со своим URL. Отдельный лендинг оправдан, только если
под него будет отдельный трафик.

### Этап 6. Статус-трекер заявки — 3–4 дня

Таймлайн в кабинете: заявка → согласование → счёт → оплата → документы → расписка →
регистрация.

Лента событий и прогресс из пяти шагов уже есть. Что добавляем:

- **Загрузка расписки о приёме документов** — новый тип вложения у заявки
  (рядом с существующими `guarantee_letter` / `lease_agreement`), загружает клиент.
- **Дата предстоящей регистрации** — поле, которое клиент указывает при загрузке
  расписки (в самой расписке дата есть, но распознавать её не нужно: пусть вводит
  руками, одно поле).
- Прогноз в трекере строится от этой даты, а не от выдуманного SLA.

Побочный эффект: появляется первая настоящая дата-дедлайн у заявки — на ней же
можно построить колонку SLA в очереди оператора, которой сейчас нет.

Шаги «отправлены в ИФНС» и «статус в ИФНС» из макета не делаем: сервис документы
в ИФНС не подаёт, подаёт клиент.

### Этап 7. Чат-бот с типовыми вопросами — 2–3 дня

Типовые вопросы уже собраны в блоке FAQ. Начинаем со статического бота по сценарию,
без модели: он закрывает большую часть обращений и не требует модерации ответов.

### Этап 8. Проверка адреса на массовость — 3–5 дней + выбор поставщика

Инструмент: клиент вводит свой адрес и получает оценку.

**Что выяснилось про источники (проверено 2026-07-28):**

| Источник | Состояние |
| --- | --- |
| pb.nalog.ru — сервис «Прозрачный бизнес» | Данные актуальные, обновляются еженедельно. **Открытого API нет.** Официальный API у ФНС есть только для электронной регистрации юрлиц (заявка на `api-regservice@tax.gov.ru`) — это другое |
| Набор открытых данных ФНС `7707329152-masaddress` | CSV со списком адресов и числом юрлиц по каждому. **Заморожен: последнее обновление 09.05.2021, помечен «не подлежит дальнейшему обновлению»** — как единственный источник не годится |
| Платные прокси к pb.nalog.ru (api-fns.ru, api-cloud.ru, parser-api.com) | Отдают JSON по тем же формам. Неофициальные: живут ровно столько, сколько ФНС не меняет вёрстку |
| DaData — уже подключена и оплачена | Массовости и числа компаний по адресу **не отдаёт**. Но отдаёт `address.invalidity` — отметку ФНС о недостоверности сведений об адресе (код + судебное решение) |

Отсюда порядок работ:

1. Сначала выводим то, что доступно сегодня без новых договоров: признак
   недостоверности адреса из DaData. Это половина ценности инструмента и ноль
   дополнительных затрат — у сервиса уже есть и клиент DaData, и circuit breaker
   к нему (`app/services/dadata.py`).
2. Параллельно выбираем поставщика по массовости: платный прокси к pb.nalog.ru
   либо собственный запрос к pb.nalog.ru. Второе — риск: captcha, отсутствие SLA
   и условия использования сервиса.
3. Эндпоинт + кэш + ограничение частоты. Кэш обязателен: адрес меняет статус
   раз в неделю, а запрашивать его будут постоянно.

Критерий массовости для формулировок (приказ ФНС от 11.02.2016): более 10 юрлиц
по адресу для зарегистрированных после 01.08.2016.

### Этап 9. Калькулятор стоимости и рисков — 4–6 дней, зависит от этапа 8

Вилка цен считается по каталогу уже сегодня. Рисковая часть («по этому адресу
зарегистрировано N компаний») опирается на данные из этапа 8.

Формулировку «высокая доля отказов в ИФНС №…» не делаем: сервис не знает исхода
регистрации по своим заявкам, считать долю не из чего.

### Этап 10. Скоринг арендатора — 3–5 дней + юридическое решение

Профиль арендатора для собственника: возраст компании, статус, учредители,
исполнительные производства, арбитражные дела.

**Технически** — источник выбран (rusprofile.ru или аналог), но перед договором
нужно проверить по документации поставщика, что в ответе действительно есть ФССП
и картотека арбитражных дел, а не только выписка ЕГРЮЛ. Часть данных при этом уже
доступна через оплаченную DaData: дата регистрации, статус (действующая /
ликвидируется), учредители, руководители, отметка о недостоверности сведений.
Если у поставщика нет ФССП — у ФССП есть собственный API с токеном
(`api-ip.fssp.gov.ru`); картотека арбитражных дел открытого API не имеет.

**Юридически** — это передача сведений об арендаторе третьему лицу (собственнику).
Нужно заключение юриста: какие данные показывать, на каком основании и с каким
уведомлением арендатора. До заключения не начинать.

## 4. Что из замечаний сделано иначе и почему

| В замечаниях | Как сделано | Почему |
| --- | --- | --- |
| «Более 24 проверенных адресов с гарантией регистрации в ИФНС» | не публикуем | адресов 26, все демонстрационные; «гарантия» — обязательство, которого нет в оферте |
| «24 адреса — все проверены на массовость», «9 ИФНС — покрытие Москвы» | счётчики остались фактическими (считаются из каталога), пояснения не добавлены | московских адресов 6 из 26; проверки на массовость нет — она появится в этапе 8 |
| «Собственник подтвердит готовность в течение 24 часов» | «Собственник получит уведомление и подтвердит готовность» | сроков на бэкенде нет |
| «Статус „Оплачено“ отобразится сразу после транзакции» | «Статус оплаты отображается в личном кабинете» | приём платежей ручной, статус ставит оператор |
| «Скачайте комплект в кабинете и на email» | «Комплект появляется в личном кабинете» | почта отправляет только подтверждение адреса, сообщения чата и отзывы; комплект письмом не уходит |
| «Документы подготовлены строго по требованиям ФНС» | вынесено тезисом на первый экран: «Документы соответствуют требованиям ФНС» | уточнение к первой редакции этой строки: договор и гарантийное письмо сервис **генерирует сам** по своим шаблонам (`app/services/document_generation.py`, `templates/*.docx`) — от собственника приходят только выписка ЕГРН и фото. За формулировку отвечает тот, кто правит шаблоны |
| «Гарантируем право собственности» | «Подтверждаем право собственности» | «гарантируем» = ответственность за чужие права на объект |
| «Сдай адрес легально — зарабатывай от 10% с каждой сделки» | «Сдайте свой адрес в каталог», без процента | расчёта комиссии в коде нет вообще |
| «Выплаты в течение 24 часов после оплаты клиентом» | «Комиссия удерживается только при успешной сделке» | механизма выплат нет; обещанный срок стал бы основанием для претензии в первый же месяц |
| «Часть клиентов приходит из реферальной сети бухгалтерских сервисов» (было на сайте) | убрано | такой сети нет |
| «Выделяем жирным важные цифры: 24 часа, 30 дней, 15–30 минут» | не сделано | этих сроков в текстах не осталось — выделять нечего |
