# Выплаты собственникам

Ветка `feat/owner-payouts` (от `feat/tbank-acquiring`), 12.10.2026.

## Правило

Если деньги клиента принимает площадка (эквайринг Т-Банка), она перечисляет
собственнику **цену за вычетом своей комиссии**, и только после того, как
**компания клиента зарегистрирована по адресу**. Это решение владельца от 12.10.2026.
Оплата по счёту собственника (`manual_invoice`, смена адреса) идёт мимо площадки,
поэтому выплаты по ней нет. Модель денег описана в `CLAUDE.md`, раздел «Как устроены
деньги».

Переводы делаются **вручную**: система ведёт реестр, админ платит в банке и отмечает
выплату. Автоматические выплаты через API банка требуют отдельного договора с Т-Банком.

## Жизненный цикл

```
оплата прошла ──► awaiting_registration ──► due ──► paid
                          │                  │
                          └──── cancelled ◄──┘
```

| Шаг | Кто | Что происходит |
|---|---|---|
| Оплата | банк | `tbank_payments._on_paid` → `owner_payouts.ensure_payout`. Процент и суммы фиксируются на этот момент. DEMO-терминал выплат не порождает. |
| Расписка | клиент | После выдачи документов загружает PDF расписки ИФНС из письма. Дата регистрации из неё строит прогноз трекера и напоминание админу. Расписку видит собственник. Скан без текста и PDF без признаков расписки (нет ни слов расписки, ни инспекции ФНС) не принимаются. Разбор идёт в потоке, с пределами по размеру содержимого и числу операторов: маленький «тяжёлый» PDF не займёт воркер. |
| Сверка | админ | «Проверить регистрацию». **Первичная**: поиск в ЕГРЮЛ (DaData) по названию из расписки, иначе из заявки; у кандидатов отметки «название / адрес совпадает». **Смена адреса**: по ИНН компании из заявки, вводить ничего не нужно, другой ИНН не принимается. Кэш DaData сбрасывается. |
| Подтверждение | админ | Выплата переходит в `due`, снимок сверки сохраняется в `applications.registration_check`. Собственнику и клиенту приходит уведомление. Если название или адрес не совпали, подтвердить можно только с отметкой «сверено вручную». Регистрацию можно подтвердить и у заявки без выплаты (счёт собственника), это последний шаг трекера. Если выплату двигать нельзя (её отменили, клиенту возвращали деньги), регистрация всё равно подтверждается, выплата остаётся как была, а причину админ видит в окне сверки (`payout_held`). Когда блокировка снята (например, возврат не прошёл), админ подтверждает ещё раз из реестра, и выплата переходит «к перечислению». |
| Выплата | админ | Переводит деньги в банке и нажимает «Деньги отправлены» (дата и номер платёжки). Реквизиты получателя сохраняются снимком. Без расчётного счёта и БИК у собственника выплату отметить нельзя. Собственнику приходит уведомление. |
| Отмена | админ | С причиной, только до выплаты. Если выплата была «к выплате», собственнику приходит уведомление. |

**Видимость для собственника.** Выплаты видны только по заявкам, которые ему уже
показываются в кабинете (`OWNER_VISIBLE_STATUSES`). Оплаченная заявка до назначения
админом скрыта.

**Сверка адреса.** Номера сравниваются по видам: дом, корпус, строение, помещение.
Лишний корпус или строение в ЕГРЮЛ означает другое здание. Все значимые слова нашего
адреса, включая улицу, должны найтись в ЕГРЮЛ. Админ получает предупреждения, если ИНН
уже подтверждён по другой заявке или (при смене адреса) не совпадает с компанией из
заявки.

**Блокировки** проверяются на каждом шаге по живому состоянию: возврат клиенту (полный
или частичный), спор, отмена заявки. Они держат выплату, но не регистрацию: факт
регистрации — шаг трекера клиента и собственника. Подтверждать регистрацию можно только
после выдачи документов (`ready_for_client` / `completed`).

## Процент комиссии

- У собственника — `providers.commission_percent`, меняет только админ:
  «Собственники» → «Выплаты» (`PATCH /providers/{id}/payout-settings`).
- Если у собственника процент не задан, действует общий `OWNER_COMMISSION_DEFAULT_PERCENT`,
  по умолчанию **19%** (решение владельца 12.10.2026).
- Если не задан и он, выплата ждёт: суммы появятся при подтверждении регистрации, когда
  процент уже будет задан.
- Комиссия округляется до копейки, выплата — остаток, так что сумма всегда сходится.
  База дополнительно проверяет это через CHECK.
- Комиссия эквайринга — расход площадки (решение владельца). Из выплаты она не вычитается.

## Реквизиты

Реквизиты собственника меняет **только админ**, там же, где процент. Если собственник
сможет сам менять счёт для выплат, при взломе его аккаунта выплаты можно будет увести на
чужой счёт.

## Не сделано

- Мобильное приложение: поле ИНН есть только в вебе.
- Документы на выплату (акт, отчёт агента): ждут ответа бухгалтера,
  `docs/accountant-question-settlements.md`.
- Комиссия, которую собственник платит площадке при смене адреса, будет отдельной
  задачей (решение владельца).
- Выгрузка реестра в файл для банка.
- Возврат клиенту **после оказания услуги** рассматривается индивидуально (решение
  владельца 12.10.2026). Система такой возврат не блокирует. Если собственнику уже
  заплатили, вернуть деньги с собственника — решение админа вне реестра.
- Отменённую выплату нельзя переоткрыть: если деньги всё же положены, расчёт идёт
  вне реестра.
